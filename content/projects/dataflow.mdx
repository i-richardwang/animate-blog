> 无代码配置 AI 数据清洗流程。上传 CSV，描述处理规则，让 AI 代理自动完成大规模实体标准化、分类归档等数据处理任务。

企业数据治理中，实体标准化是最耗时的环节之一。同一家公司可能有几十种不同的写法，同一所学校在不同系统中名称各异。传统方案要么依赖人工逐条核对，要么需要编写复杂的规则引擎。当数据量达到万级以上，两种方案都难以为继。

DataFlow 将这个过程简化为：**配置处理规则 → 上传数据 → 等待结果**。AI 代理会自动理解语义、查询历史映射、调用外部知识，确保处理结果的一致性和准确性。

前端使用 Next.js 15 构建，通过 Server Actions 与后端 API 通信。后端采用 FastAPI 接收请求，Celery 分发任务到 Worker 执行。每个任务由 LangGraph 编排的 AI 代理处理，代理可以调用向量搜索、SQL 查询、外部搜索等工具。

## 核心功能

### 配置化代理

通过 JSON 配置定义 AI 处理行为，无需编写代码：

```json
{
  "scenario_name": "company_standardization",
  "model_name": "openai:gpt-4o-mini",
  "prompt": "将输入的公司名称标准化...",
  "output_model": {
    "name": "CompanyResult",
    "fields": [
      { "name": "standardized_name", "type": "string" },
      { "name": "industry", "type": "string" },
      { "name": "company_type", "type": "string" }
    ]
  },
  "available_tools": ["query_mapping", "store_mapping", "tavily_search"],
  "storage_schema": {
    "domains": {
      "company_mapping": { "mode": "vector" },
      "company_categories": { "mode": "sql" }
    }
  }
}
```

配置包含：场景名称、使用的模型、提示词、输出字段定义、可用工具列表、存储策略。系统会根据配置动态创建代理实例。

### 双域内存系统

采用向量数据库 + SQL 数据库的混合存储策略：

| 存储类型 | 用途 | 查询方式 |
|---------|------|---------|
| **向量域** | 原始输入 → 标准名称映射 | 语义相似度搜索 |
| **SQL 域** | 标准名称 → 分类属性 | 精确匹配查询 |

当处理新数据时，代理首先在向量域中搜索语义相似的历史记录，找到则直接复用映射结果；未找到则进行推理，并将新映射存入两个域供后续使用。这确保了跨会话的结果一致性。

### 实时任务监控

通过 Server-Sent Events (SSE) 推送任务执行的每一步：

- **agent 节点**：AI 的思考过程和决策
- **tool 调用**：向量查询、SQL 查询、外部搜索的结果
- **memory 命中**：是否复用了历史映射
- **最终输出**：结构化的处理结果

前端实时展示这些信息，让用户清晰了解 AI 的处理逻辑。

### 批量处理能力

- 支持 100MB 以下的 CSV 文件
- 自动检测 UTF-8、GBK、GB2312 编码
- 单个作业最多处理 10,000 条记录
- 任务级别的重试机制和超时控制
- 处理完成后自动生成结果 CSV

## 适用场景

**企业名称标准化**：将「腾讯」「深圳市腾讯计算机系统有限公司」「Tencent」统一为标准名称，并补充行业分类。

**学校名称归一**：处理简称、全称、历史名称的映射，如「北大」→「北京大学」。

**产品品牌识别**：从用户输入中提取标准化的品牌和产品型号。

**简历技能标准化**：将多样化的技能描述归类到标准技能体系。

**客服工单分类**：自动对用户反馈进行主题分类和优先级标注。

通过配置不同的场景模板，同一套系统可以处理多种数据清洗任务。
