一个 Agent 同时接入多个工具后，光是让模型知道这些工具怎么用，就要占用不少上下文。MCP server 注册的所有工具都会把名称、参数和说明一起交给模型。一次任务通常只会用到其中一小部分，其他工具的说明也会一起进入上下文。

CLI 的命令说明只在使用时加载。Agent 平时只需要知道系统里有哪些 CLI，执行任务时再查看具体命令的帮助。[OpenClaw](https://github.com/openclaw/openclaw) 就采用了这种方式，让 Agent 通过 CLI 命令和 shell 脚本调用工具；配套的 [mcporter](https://github.com/ShadM00/openclaw-mcporter) 还可以把现有 MCP server 转成 CLI。

我们开发 [Tableau CLI](/projects/tableau-cli) 时，起点也是一套现有的 MCP 实现：Tableau 官方的 [tableau-mcp](https://github.com/tableau/tableau-mcp)。在此基础上，我们按照 Agent 实际执行的任务重新整理了命令。后面的讨论主要来自这次开发过程，Dossier 和 DataPilot 中的相关做法会作为补充。

## CLI 在上下文效率上的优势

MCP Tool 是直接提供给模型调用的。server 启动后，注册的工具会连同名称、参数和说明一起进入上下文。Tableau MCP 里有十几个这样的工具，一项任务通常只会用到其中一两个，模型却已经读过了整套定义；再接入其他 MCP server，这部分内容还会继续增加。

CLI 不会提前把每条命令都交给模型。Agent 一开始只拿到一个简短的入口，等它确定要做什么，再读取对应的 `--help` 或命令手册。当前命令的细节到这时才进入上下文，没有用到的命令始终不会出现。

## 按照 Agent 的使用方式设计 CLI

### 按任务组织命令

以查询数据源的元数据为例。Tableau 的完整信息分散在两个 API 里。如果 CLI 仍按 endpoint 提供命令，Agent 就要分别调用它们，再把结果合到一起。

Tableau CLI 把这些处理收进了 `ds metadata`。这条命令会查询两个 API，其中一个不可用时自动降级。Agent 只需调用这一条命令，不必了解 Tableau 的接口是怎么拆分的。

CLI 里保留哪些命令，也按照 Agent 实际要做的事情来决定。Tableau REST API 还提供创建用户、修改权限等站点管理能力，这些没有放进 CLI。Agent 看到的都是搜索内容、使用数据源和导出视图等分析命令。

### 裁剪响应内容

Tableau 的搜索接口面向各种客户端，一条结果里会带上很多字段，比如所有者邮箱、创建时间、不同时间区间的访问次数，以及页码、起始位置等分页信息。这些字段在不同场景里都有用途，但具体到一次搜索任务，Agent 通常只会用到其中一部分。

例如搜索“销售看板”时，Agent 需要知道内容的名称、类型、所属项目、使用情况，以及下一步操作要用的 ID。Tableau CLI 会在输出前保留这些信息，删掉其余字段，避免它们随着每条搜索结果反复进入上下文。

留下来的结果也会做简单整理：重复的数据源只保留一条，含义不直观的字段名称会改得更明确。Agent 拿到结果后可以直接继续查询或导出，不必先研究 Tableau 接口的返回格式。

### 错误信息引导 Agent 自动恢复

Agent 调用 CLI 时，遇到的很多错误都有明确的处理办法。字段名写错后，可以先查看可用字段，再修改命令；服务没有开启，需要找到对应的配置说明；查询返回的数据太多，也可以缩小范围后重试。底层 API 返回的错误码或异常文本通常只说明发生了什么，没有告诉 Agent 接下来该怎么做。任务因此停下来，原本可以自动完成的修正只能交给用户。

Tableau CLI 会在已知错误的响应里增加一个 `hint`，给出下一步可以执行的操作：

```json
{
  "isError": true,
  "errorType": "Unknown field",
  "message": "Unknown field: The requested field doesn't exist.",
  "hint": "Use `tableau-cli datasources metadata <luid>` to see available fields and their exact names."
}
```

这个例子里，`message` 说明查询使用了不存在的字段，`hint` 进一步告诉 Agent 应该运行哪条命令。拿到正确的字段名后，它可以修改原来的查询，继续执行。服务配置缺失、查询范围过大等情况，也会给出对应的处理建议。其中的错误分类和描述沿用了 tableau-mcp 的实现，Tableau CLI 在此基础上补充了用于恢复的 `hint`。

[Dossier](/projects/dossier) 是一个用知识图谱做组织情报研究的系统。它在写入实体时会先检查记录是否已经存在，遇到重复实体便返回已有记录的 ID。Agent 可以拿着这个 ID 继续后面的操作，任务不会因为一次重复写入中断。

## Skill 分层与渐进式加载

CLI 不会在任务开始时把所有命令说明一起交给模型。不过，Agent 仍然要知道工具能做什么、具体命令怎样使用，这些内容通常写在 Skill 里。Skill 可以理解为 Agent 使用工具时读取的操作说明。如果所有内容都塞进同一个文件，Agent 每次使用 CLI 时还是要读完整本手册，前面节省下来的上下文又会被占回来。

Tableau CLI 把配套文档拆成一个入口和两份参考资料：

```text
skills/
├── SKILL.md              # 入口：任务判断和环境检查
└── references/
    ├── cli.md            # 完整命令手册
    └── installation.md   # 安装和认证配置
```

当任务需要使用 Tableau 时，Agent 先读取五十行左右的 `SKILL.md`。这个入口会检查 CLI 是否可用，也会告诉 Agent 不同任务应该去哪里查找说明。比如用户想下载数据源做本地分析，入口中会给出大致流程，具体参数和命令示例仍然放在 `references/cli.md` 里。

Agent 准备执行命令时才读取 `references/cli.md`。`SKILL.md` 里还写了一条明确的规则：`Do not guess command syntax from memory`。即使 Agent 熟悉常见的 CLI 用法，也必须查看这份手册确认参数，避免凭印象拼出一条不存在的命令。

安装和认证说明单独放在 `references/installation.md`。只有 CLI 尚未安装或配置缺失时，Agent 才需要读取它。已经配置好的环境在执行搜索、下载或查询任务时，不会把这部分内容带进上下文。

Dossier 的 CLI 覆盖了更多工作流，把所有说明继续写在同一个入口里也会越来越长。它将数据录入、深度研究和质量检查等工作流拆成独立的 Skill，每个研究项目再用单独的 context 文件记录背景和待解决的问题。Agent 只需读取当前工作流和当前项目的内容；增加新的研究主题时，也只需要补充对应的背景文件。

完整说明仍然保留在项目里，只是按照任务和环境分开存放。大多数时候，进入上下文的只有简短入口，命令手册和安装说明在需要时才会加载。

## CLI 是应用，不只是接口封装

现在常见的 MCP 多通过 HTTP 接入。Agent 调用工具时，代码实际运行在远程的 MCP server 上，使用的也是服务端的文件、依赖和进程。对于 Tableau 这类在线系统，MCP 的能力通常围绕已有 API 展开：接收请求、调用接口，再把结果返回给 Agent。

CLI 直接运行在 Agent 当前的环境里。它可以调用远程 API，也可以继续处理下载到本地的文件、使用本地安装的库，或者启动其他程序。API 调用和后续的本地处理可以放在同一套命令里。

Tableau CLI 的 `convert` 命令就是一个例子。Tableau API 可以下载数据源文件，但得到的是 `.tdsx` 格式，Polars 和 Pandas 等常用分析工具无法直接读取。CLI 会在本地提取其中的数据，再转换成通用的 Parquet 或 CSV，整个转换过程不再调用 Tableau API：

```bash
tableau-cli ds download <id> -o ./data/         # 从 Tableau 下载数据源文件
tableau-cli convert ./data/data.tdsx -o ./data/ # 在本地转换为 Parquet
# Agent 接下来可以使用 Polars 或 Pandas 分析
```

格式转换使用的是客户端的 CPU 和内存。服务器在这一步只需要提供原始文件，不必为每个用户承担转换任务，也不用为格式转换单独配置依赖和计算资源。使用 CLI 的客户端越多，这些处理仍然分散在各自的环境里，不会全部集中到同一个服务端。

转换所需的数据处理库与 CLI 的核心功能分开管理。只使用搜索、查询或下载功能时，不需要额外安装这些依赖；当前环境无法执行转换时，CLI 会在错误信息里说明该怎样处理。

[DataPilot](/projects/datapilot) 是一个带 CLI 的 Agent 运行平台。它的 `run` 命令会在本地启动分析 Agent 服务，任务结束后再将其关闭。调用方只需要执行一条命令，本地服务的启动和退出都由 CLI 负责，运行任务所需的计算资源也由当前客户端承担。

## 结语

把 API 包成命令，只解决了 Agent 能不能调用工具。一次任务真正跑起来以后，接口怎样拆分、返回结果里哪些信息有用、出错后怎么继续，仍然可能都要模型自己判断。CLI 如果止步于接口映射，只是把底层系统的复杂度换了一种形式交给了 Agent。

这篇文章里的设计，都在避免 Agent 反复处理这些细节。做法已经明确的事情由工具完成，Agent 负责理解用户要什么，并在任务发生变化时作出选择。CLI 和 MCP 提供了不同的实现方式，但无论使用哪一种，工具有没有替 Agent 承担好这部分工作，都会直接影响它是否真正好用。

> 注：Tableau CLI 的 REST API、VizQL Data Service、Metadata API 集成和错误分类，基于 Tableau 官方的 [tableau-mcp](https://github.com/tableau/tableau-mcp)。
