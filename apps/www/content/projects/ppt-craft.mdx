PPT Craft 是一个面向 AI Agent 的统一 PPT 处理方案。它将 PPT 相关的操作收敛为"从零创作"和"修改已有文件"两条主线，并提供配套的工具链、操作规范与辅助脚本。这套方案以指令集和脚本的形式存在，可以灵活集成到各类 Agent 的工作环境中。系统采用按需加载（On-demand Loading）架构，通过动态路由将用户的操作请求分流至对应的处理路径，避免全量加载无关指令而增加上下文负担。

## 动态路由与按需加载

入口会根据任务上下文中是否存在现成的 PPT 文件，将操作意图分流，并渐进式加载相应的依赖与子指令：

| 处理主线 | 适用场景 | 核心工具 | 适用范围 |
| --- | --- | --- | --- |
| **从零创作** | 无现成 PPT 输入。包括新建图表页、构建高信息密度页面、根据参考图进行 1:1 复刻 | pptxgenjs (Node.js) | 数据驱动的页面生成、结构化总结输出 |
| **修改已有** | 有现成 PPT 输入。包括按模板批量生成、修改现有页面、提取内容与格式转换 | python-pptx (Python) | 模板数据填充、局部内容更新、跨版本合并对比 |

## 从零创作：坐标级布局控制

在无模板输入的场景下，直接使用 pptxgenjs 在 10″ × 5.625″ 坐标系内进行布局计算与绘制。

**设计系统统一管理**
所有生成的页面统一引用 `theme.js` 配置文件。该文件集中管理主色调（如 `#456AF0`）、字号常量及页面骨架（标题、卡片、页码等组件），保证多页拼装后的视觉一致性。

**高级图表与样式支持**
针对常规方案无法覆盖的复杂图表，内置了以下实现方式：
- **自定义数据标签**：根据绘图区边界估算坐标，通过叠加独立文本框实现自定义格式。
- **正负向横向柱状图**：使用形状组件进行逐行手绘。
- **复杂路径与渐变填充**：先生成基础 PPT 文件，随后利用 JSZip 注入原始 `custGeom` XML。

**1:1 精确复刻**
复刻场景需要提取原始 PPTX 的 XML 数据并在代码中还原。配套的 `extract_shapes.py` 脚本可自动化处理以下换算逻辑，并输出可供 pptxgenjs 使用的坐标参数：
- 将 PowerPoint 标准尺寸缩放为 pptxgenjs 的布局比例（系数 0.75）。
- EMU 单位与英寸的换算（914400 EMU = 1 英寸）。
- Group 组合形状内子元素的 `transform` 相对坐标计算。
- 主题相对色（`schemeClr`）向绝对色（`srgbClr`）的转换。

## 修改已有：模板解析与数据填充

针对模板化输出场景，使用 python-pptx 进行操作，并要求严格遵循"结构解析 -> 字段映射 -> 数据更新"的流程。

**双向结构解析**
通过 `analyze_template.py` 脚本扫描目标页面，输出形状的名称、类型、位置、文本内容及图表信息：

```bash
# 解析指定页面的模板结构
python <skill-path>/scripts/analyze_template.py template.pptx 2
```

获取模板结构后，结合 pandas 解析出的数据源 sheet 结构，进行字段映射确认。对于占位文本与列名不一致的情况，明确作为待确认项交付。

**基于语义的形状定位**
为避免模板编辑导致形状层级或索引变化（如 `shapes[3]` 变动），关键形状需要在模板中按语义前缀重命名，代码统一通过 `shape.name` 定位目标元素。文件目录隔离为只读的 `raw`、暂存过程文件的 `working` 及产出最终文件的 `output`。

**格式安全的文本更新**
修改占位文本时，操作限制在 `run.text` 层级，以保留原有的字体、颜色和字号等格式信息：

```python
# 保留格式的文本更新方式
paragraph.runs[0].text = "新文本"
```

**批量生成的流程控制**
- 在执行批量循环前，先输出单份样品进行抽样核对。
- 循环体内每轮重新加载原始模板，防止跨循环的状态污染。
- 面对差异化模板，通过 `group` 参数进行路由分流或拆分为独立函数处理。
- 针对无法通过 python-pptx 改写的 OLE 对象（如 think-cell 图表或嵌入的 Excel），执行时会自动跳过并在日志中进行标记。

## 生成后视觉校验

无论是新建还是修改，代码执行完成后需将产物转换为图像进行最终核对，以验证布局是否正确。

```bash
# 使用 LibreOffice 转为 PDF
soffice --headless --convert-to pdf output.pptx

# 将 PDF 转为图像逐页检查
pdftoppm -jpeg -r 150 output.pdf slide
```

在缺少 LibreOffice 的环境中，降级使用 markitdown 提取文本进行校验，并在交付时注明需人工抽查视觉版式。

## 场景化评测

该方案包含一套基于真实报告的评测用例（详见 [Better Skills](/projects/better-skills)），包含三个梯度的场景验证：
- **模板结构解读**：解析两份模板，结构化输出指标占位符、模板差异及 OLE 嵌入对象。
- **单份报告生成**：输出一份报告，并根据数据源的真值断言校验数值误差。
- **多版本混合渲染**：5 个组织混合两套不同模板进行批量填充，确保路由分流准确。

## 技术栈

- **从零创作**：Node.js、pptxgenjs、JSZip（XML 注入）
- **修改已有**：Python、python-pptx、pandas（数据源解析）
- **辅助工具**：`analyze_template.py`（模板分析）、`extract_shapes.py`（坐标换算）
- **校验依赖**：LibreOffice (`soffice`)、`pdftoppm`，备选降级方案 `markitdown`
